# Stakeholder dashboard

## Interface

`index.html`, `styles.css`, `app.js`, and `assurance.js` serve seven hash-routed views. The assurance view uses a separate measured `assurance.json` and printable `assurance_report.html`. `benchmark.json` is generated by training and required for evidence views; `report.html` and `model_metrics.csv` are generated exports. `GET /api/health` and `POST /api/score` are optional local-server capabilities. Static hosting cannot provide new model inference.

## Invariants

All reported model metrics come from the measured run. Browser budget and cost controls create retrospective scenarios only. Labels are explicitly historical. User search text is escaped. CSV inputs are validated before the API validates them again. Feature detail exists only for the exported high-risk subset; unavailable detail is stated explicitly.

## Side Effects

Loads local static evidence. Hash navigation updates the URL. User-triggered exports create browser downloads. Scoring sends anonymized feature data only to the same-origin local API. No analytics, external font, chart CDN or cookies are used. User-entered research reviews can persist through the local API in run-scoped SQLite; scoring transaction inputs are not saved.

## Verification

`node --check web/app.js`. Serve using `python run.py serve`; inspect the overview, policy changes, model curves, case dialog/filter, data-health view, report downloads and scoring success/error states. See [review evidence](../docs/review.md).

Extension checks: `node --check web/assurance.js` and `node tests/test_assurance_ui.cjs` exercise the measured assurance view, task separation and review-dialog race guards. See [extension review](../docs/assurance_review.md). Static/offline viewing supports all evidence and exports; new scoring and review writes require the local API.
